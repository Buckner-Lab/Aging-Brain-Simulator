# Analysis scripts for Buckner et al., AgingBrain Simulator

Scripts that reproduce the numbers behind each panel of Figures 1–8 of the paper, run inside the simulator files the paper used.
Package date 261110 (2026-11-10). The context comes first; the index of every script is at the end.

## What the scripts are

- One file for each panel of Figures 1–8, 40 in all, named `Buckner_etal_Figure<N>Panel<L>_261110.md`.
- Each file opens with a few lines: the panel, the simulator file and version it uses, the command that runs it, what the panel shows and how
  the script computes it, and the values the paper reports (`Paper:`) or the figure shows (`Figure:`). Below them is one block of JavaScript,
  the analysis. The six panels that are diagrams or screenshots have a note instead of code.
- `run_panel_261110.mjs` runs one script and prints what it returns as plain-text tables.
- `expected_output_261110.txt` holds the output of every script from the run that made this package, for comparison.
- The simulator files are the paper's own and keep their own dates: version 99 (`AgingBrain_Simulator_261023.html`) for Figures 1–6 and 8,
  version 88 (`AgingBrain_Simulator_261014.html`) for Figure 7, and the version 91 branch (`AgingBrain_Simulator_v91_261018.html`), the
  source of Figure 5F's generational settings.

## How they reproduce the paper's figures

- **They run the simulator itself.** Nothing in the model is re-implemented. The runner opens the file a script names in headless Chromium, adds
  one line that gives the script the application's scope, waits for the default world (seed 7, 120,000 lives born 1926–2008, study year 2026)
  and runs the block. The code then calls the same engine and stage functions that the application's buttons call, for example `E.trace` (one
  life, year by year), `runSelection`, `msStats`, `anRecs`, `ivArms` and `wpChecks`. The developer guide inside the file describes them.
- **They are deterministic.** Every world and draw is seeded, so the same file and settings give the same numbers on any computer. Settings
  that differ from the defaults are set in each script's first lines (a strategy, its ages, sample size, draw number). Worlds with other
  parameters are simulated anew inside the script (Figures 5F and 7).
- **They reproduce numbers, not drawings.** Each script returns the counts, means, slopes, correlations, shares and check results that a panel
  plots or that the text and legends quote. Axes, colors and layout are not part of the scripts.
- **One declared edit.** Figure 5F needs generational change in rates of aging, which version 99 lacks; it comes from the version 91 branch. The
  script carries four `patch` blocks (old text, `=>`, new text) that the runner applies to its temporary copy of version 99 before loading.
  The simulator files themselves are never changed.
- **Checked.** All 40 scripts were run from this folder before packaging. For every panel with a script, the numbers the paper states in its
  text and legends came out the same, except the small differences for Figure 5E described below.

## Where they cannot reproduce a panel, and why

- **Diagrams (1A, 2A, 8A).** These are drawn, not computed, so each has a note. 1B and 8D are diagrams too, but their scripts check what they
  depict: the dementia rule and the MMSE when dementia begins (about 24), the 12 of 13 reality checks, the versions in the file, and the
  milestones in its version history.
- **Screenshots (7E, 8B, 8C).** 7E shows the application's own plot and its list of insights and puzzles, kept inside version 88; its note
  says where to find them in that file. 8B and 8C show files that fresh
  AI agents built from version 78 (`LifeBrain_Simulator_261010_v78.html`, marked 78* in the index). Those files are not part of the
  distribution, so their values cannot be rerun here. The Methods describe how to rebuild them by giving version 78 and the prompt to a new agent.
- **Figure 5E, within 0.2 points.** The script draws the norm group's measurement errors with its own generator (seed 12345), not the original
  analysis script's draws, so four shares differ slightly: D 19.7% (paper 19.9%), S 15.8% (15.7%), M 6.2% (6.0%) and B 27.9% (27.8%). The
  H share (6.4%) and every count match.
- **Choices the paper does not state, recovered from the figures.** Figure 2F's second sample is the application's draw 282, the only one of
  the first 400 draws whose counts match the figure (2C–2E, 2G and 2H use draw 1). Figure 2B draws links smaller than 0.02 SD at 85 as open
  circles, a cutoff read from the figure (its smallest filled dot is 0.025 SD, its largest open one 0.012 SD). Figure 2G shows the participants
  aged 81–90 at entry, with the dashed line for everyone alive at 81–90, as in the figure's key.
- **Supplementary figures.** Not covered by this package.

## Running a script

    npm i playwright && npx playwright install chromium     # once; Node 18 or later
    node run_panel_261110.mjs Buckner_etal_Figure6PanelF_261110.md

Keep the scripts and the simulator files in one folder, or give the folder holding the simulator files as a second argument. Loading the
world takes about 20 s; most scripts then finish within seconds. 5B–5F and the Figure 7 scripts, which simulate worlds again, take up to
about 2 minutes. The paper ran the engine in Node.js for its whole-world comparisons (Figures 3, 5F and 7); the scripts run the same engine
code in Chromium and give the same numbers.
